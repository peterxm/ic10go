# 多芯片 `str("...")` 通道验证（P0）

目的：确认 `STR("...")` 是否只是**编译期原样操作数**（过不了数值通道），还是
本身就是某个 float64 编码（能像 `num` 一样走通道）。这决定 `bus` 的 `str` 槽位
怎么做（见 `docs/multichip.md` §2.6、§11）。

> 结论未定前不要实现 `str` 槽位。

## 通道语义（来自社区实测，重要）

- 通道是**每条电缆网络 8 个值**（存在网络本身，不是设备属性）。
- IC 能读写**任何被引用设备的任意连接**上的通道：`d0:0`、`d0:1`、`db:0`、`db:1`…
- **两个网络不物理相连 → 读到 `NaN`（No Available Network）**。
- 通道能**穿过网络隔断设备**（APC / 变压器），但仍需要物理路径。
- 因此：两块芯片要共享通道，**必须处在同一条电缆网络**（或经桥接设备连通）。

## 接线

- 两块 IC 芯片，插在**标准 IC host** 上。
- **把两个 IC host 的数据口接到同一条电缆网络**（这是 T2 之前失败的原因：
  各自的 `db:0` 是各自那条网，不连通就互相看不到）。
  - 若两块芯片本来就在不同网络，需要一个**桥接设备**（如 Logic Memory，
    两条连接分别接两个网络），再让两边都引用该设备的连接（见 T2b）。
- 接收芯片的 `d0` 接一个 **LED 显示器**（Logic Display / 小 LED），设为
  `DisplayMode.String`（模式值 `10`）。
- 发射芯片可以不接设备。

## 测试

### T0 单芯片回环：隔离"语法 vs 接线"

接收芯片单独跑 `t0_loopback.ic`（无需第二块芯片）：

```ic
s d0 Mode 10
s db:0 Channel0 42
l r0 db:0 Channel0
s d0 Setting r0
```

**预期**：LED 显示 `42`。说明 `s/l db:0 ChannelN` 语法正确——那 T2 若失败就
只是两块芯片的网络没接通。

### T1 对照：直接写 STR 到 LED ✅ 已通过

接收芯片单独跑 `t1_direct.ic`：

```ic
s d0 Mode 10
s d0 Setting STR("AB")
```

**预期**：LED 显示 `AB`。

### T2 对照：数值走通道（同一条网络）

接收芯片跑 `t2_recv.ic`，发射芯片跑 `t2_send_num.ic`，**两个 host 数据口接同一网络**：

```ic
# t2_recv.ic
s d0 Mode 10
loop:
l r0 db:0 Channel0
s d0 Setting r0
yield
j loop
```

```ic
# t2_send_num.ic
loop:
s db:0 Channel0 42
yield
j loop
```

**预期**：LED 显示 `42`。若仍为 `NaN`/0，检查两个 host 是否真的在同一条电缆网络。

### T2b 对照：跨网络 + 桥接（可选）

两块芯片在不同网络时，用一块 **Logic Memory** 做桥：

- Logic Memory 的两条连接分别接网络 A、网络 B。
- 网络 A 的芯片：`s memA:0 Channel0 42`（`memA` = 该芯片看到的这块 Logic Memory）。
- 网络 B 的芯片：`l r0 memB:1 Channel0`（`memB` = 它看到同一块设备的另一连接）。

**预期**：跨网络读到 `42`。验证"通道穿过桥接设备"。

### T3 关键：STR 走通道 ✅ 通过

接收芯片仍跑 `t2_recv.ic`，发射芯片换成 `t3_send_str.ic`（同一网络）：

```ic
# t3_send_str.ic
loop:
s db:0 Channel0 STR("AB")
yield
j loop
```

**实测结果**（同网络）：

| 接收端 LED 模式 | 显示 |
|-----------------|------|
| `Mode 10`（String） | `AB` |
| `Mode 0`（Default） | `16706` |

结论：`STR("AB")` = **16706 = 0x4142**（`'A'<<8 | 'B'`），是**数值编码**，能过通道；
String 模式会把该数值解回字符串。**所以 `str` 槽位可以像 `num` 一样直接过通道。**

> **LED 显示模式很严格**：同一个数值，`Mode 10`(String) 解字符串、`Mode 0`(Default)
> 显示数字；用错模式会显示 `*` 之类。这是游戏行为，脚本里要按值类型选对 `Mode`。

### T3b 长字符串 / 非 ASCII（建议补测）

`STR("AB")` 只验证了 2 字节。请再确认长字符串（可能变成 hash，显示端不一定能解回）：

```ic
# t3b_send_str.ic
loop:
s db:0 Channel0 STR("HELLO")
yield
j loop
```

以及中文：`s db:0 Channel0 STR("温度")`。分别看接收端 `Mode 10` 能否显示原文。

| 输入 | 接收端 Mode 10 | 结论 |
|------|----------------|------|
| `STR("AB")` | `AB` ✅ | 短串 = 数值编码，可过通道 |
| `STR("HELLO")` | | |
| `STR("温度")` | | |
